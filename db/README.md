# Схема базы данных «Кинопоиск»

Домашняя работа 1 по СУБД: проектирование, нормализация, ограничения целостности.

СУБД: PostgreSQL 17. Дополнительно используются Redis и объектное хранилище
S3/MinIO — они отражены на схеме и описаны в документации.

## Состав

| Файл | Содержание |
|---|---|
| `normalized/normalization.md` | приведение схемы к нормальным формам: от ненормализованного представления к НФБК, по шагам |
| `normalized/relations.md` | описание всех отношений, функциональные зависимости, доказательство 1НФ, 2НФ, 3НФ и НФБК |

## Схема

42 таблицы в PostgreSQL, 5 структур в Redis, 5 бакетов в объектном хранилище.

| Область | Таблицы |
|---|---|
| Права доступа и аккаунт | `role`, `permission`, `role_permission`, `account` |
| Файлы | `file`, `film_file` |
| Каталог | `film`, `genre`, `film_genre`, `country`, `film_country`, `similar_film`, `film_release` |
| Сериалы | `season`, `episode` |
| Персоны | `person`, `role_type`, `film_person` |
| Оценки и рецензии | `film_rating`, `film_rating_history`, `review` |
| Папки и подписки | `folder`, `folder_item`, `release_subscription` |
| Подборки | `collection`, `collection_film` |
| Уведомления и чат | `notification`, `film_discussion`, `discussion_message` |
| Модерация | `moderation_task`, `account_ban` |
| Историчность | `film_rating_history`, `film_rating_daily`, `film_revision`, `review_revision`, `account_role_history` |
| Аналитика событий | `visitor`, `traffic_source`, `page`, `event_type`, `visit`, `analytic_event`, `search_query` |

Фильмы и сериалы лежат в одном отношении `film`, тип задаёт `film_type`.
Отдельные отношения нужны только для структуры сериала: `season` и `episode`.

## Историчность данных

Версионируются пять сущностей, все журналы только на запись:

| Что версионируется | Отношение | Как заполняется |
|---|---|---|
| Оценка фильма | `film_rating_history` | триггер `write_film_rating_history` при вставке и изменении `film_rating` |
| Рейтинг фильма по дням | `film_rating_daily` | снимок на конец дня, по нему строится график |
| Карточка фильма | `film_revision` | триггер `write_film_revision` при изменении `film` |
| Текст рецензии | `review_revision` | триггер `write_review_revision` при изменении `review` |
| Роль пользователя | `account_role_history` | триггер `write_account_role_history` при регистрации и смене роли |

Автор изменения берётся из параметра сессии `app.account_id`: приложение
выставляет его через `SET LOCAL`, функция `current_account_id()` читает.

## Аналитика событий

Отдельная область для рекламной аналитики: события с фронта сохраняются в
`analytic_event` и связываются с визитом, посетителем и источником перехода.
Это позволяет считать воронку от рекламной кампании до оценки фильма.

| Отношение | Назначение |
|---|---|
| `visitor` | анонимный посетитель, связывает события до и после входа |
| `visit` | визит: источник перехода, браузер, адрес, время начала и конца |
| `traffic_source` | справочник utm-меток рекламной кампании |
| `page` | справочник страниц в виде шаблонов пути |
| `event_type` | справочник типов событий |
| `analytic_event` | само событие: просмотр, клик, открытие карточки |
| `search_query` | текст поискового запроса и число результатов |

Произвольные свойства событий не складываются в одно поле: ссылки на объекты
каталога типизированы, а специфика поиска вынесена в отдельное отношение.

## Ограничения целостности

| Ограничение | Количество | Примеры |
|---|---|---|
| PRIMARY KEY | 42 | у всех отношений |
| FOREIGN KEY | 65 | `ON DELETE RESTRICT` на пользовательский контент, `CASCADE` на личные данные, `SET NULL` на файлы |
| UNIQUE | 76 | включая `UNIQUE NULLS NOT DISTINCT` в `film_person` |
| CHECK | 104 | диапазоны, маски, согласованность пар полей, `num_nonnulls` |
| EXCLUDE | 1 | `account_ban`: блокировки одного пользователя не пересекаются во времени |
| NOT NULL | 214 | все обязательные поля |
| DEFAULT | 80 | флаги, статусы, `created_at`, `updated_at` |
| Триггеры | 31 | `set_updated_at` и ведение истории оценок |

Отдельные решения, которые стоит отметить:

- правило «сезоны только у сериала» обеспечено на уровне СУБД: в `film` есть
  уникальный ключ `(id, film_type)`, в `season` поле `film_type` закреплено
  проверкой `= 'series'` и ссылается на эту пару составным внешним ключом;
- удаление учётной записи мягкое: функция `anonymize_account()` стирает
  персональные данные, а рецензии, оценки и история остаются, потому что
  внешние ключи на них объявлены как `RESTRICT`;
- модерация вынесена в `moderation_task` и рассчитана как на человека, так и на
  автоматическую проверку моделью: у задачи есть источник решения, имя модели и
  её уверенность;
- у фильма может быть несколько постеров и трейлеров: файлы вынесены в
  отношение `file` и связаны с фильмом через `film_file` с ролью и порядком;
- симметричность `similar_film` обеспечена проверкой `film_id < similar_film_id`;
- уникальность рецензии действует только среди неудалённых строк: после мягкого
  удаления пользователь может написать новую рецензию на тот же фильм;
- дата премьеры входит в первичный ключ `film_release`, поэтому возможен
  повторный прокат.

Индексы в этой работе намеренно не создаются, кроме тех, что СУБД создаёт под
`PRIMARY KEY` и `UNIQUE`, и трёх частичных уникальных индексов, которые
выражают ограничения целостности, недоступные обычному `UNIQUE`.

## Типы данных

Используются `bigint` с `GENERATED ALWAYS AS IDENTITY`, `text` с проверкой
длины, `timestamptz`, `date`, `smallint`, `boolean`, `numeric` и `tstzrange`.
Не используются `varchar(n)`, `char(n)`, `serial`, `money`, `timestamp` без
часового пояса, а также составные типы `array` и `json`. Обоснование каждого
типа приведено в `normalized/fields.md`.

## Применение миграций

```bash
migrate -path db/migrations -database "$DATABASE_URL" up
```

Миграции написаны на чистом SQL, каждая имеет пару `up` и `down`. Миграция
000008 наполняет справочники и создаёт учётные записи, 000011 — данные аналитики,
000012 приводит правило имени пользователя к правилам бэкенда.
000013 переносит в базу каталог, который показывает фронтенд: 12 фильмов
с постерами из `static/posters`, их жанры и 4 подборки.
000014 ставит первыми настоящие постеры — внешние ссылки на изображения Кинопоиска.
